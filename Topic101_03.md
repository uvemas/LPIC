# System architecture

## Change runlevels (boot targets) and shutdwon/reboot the system

Weight: 3

### Introduction

#### SysVinit

Define un conjunto de estados llamados runlevels, numerados del 0 al 6. Cada uno de ellos se gestiona con un conjunto de scripts y tiene un propósito 
diferente:

- 0 shutdown
- 1 single user
- 2, 3, 4 multi user. Normalmente se usa el 3
- 5 multi user con arranque gráfico
- 6 reinicio del sistema

Los runlevels y sus servicios asociados los gestiona el programa `/sbin/init`. Durante el arranque, el runlevel que necesita `init` se pasa como un parámetro del kernel o se lee del fichero `/etc/inittab`. El fichero `inittab` está formado por líneas con el formato `id:runlevels:action:process`.

- id es un ID de hasta 4 caracteres que identifica la línea
- runlevels es una lista de números de runlevel para los que se ejecutará el proceso indicado en esa línea
- action indica como afecta la ejecución de `process` al proceso `init`
- process es el proceso a ejecutar

Por ejemplo:

~~~ zsh
# Default runlevel
id:3:initdefault:

# Configuration script executed after system initialization. The field runlevels is ignored
si::sysinit:/etc/init.d/rcS

# Actions taken on runlevel 3. init will wait until process finishes to continue
~:S:wait:/sbib/sulogin
l3:3:wait:/etc/init.d/rc 3

# Action taken upon CTRL+ALT+DEL keystroke
ca::ctrlaltdel:/sbin/shutdown -r now

# Enable consoles for runlevels 2 and 3. The process will be restarted if it is terminated
1:23:respawn:/sbin/getty tty1 VC linux
2:23:respawn:/sbin/getty tty2 VC linux
~~~

Si se modifica la configuración de `inittab` hay que recargarla con `telinit q`.

Los scripts que necesita `init` para hacer el setup de cada runlevel están en `/etc/init.d`. 

Los scripts que hay que ejecutar/detener son links simbólicos que hay en `/etc/rc0.d`, `/etc/rc1.d` y que apuntan a `/etc/init.d`. Los enlaces que empiezan por S arrancan servicios y los que empiezan por K matan servicios.

Para saber en que runlevel estamos usamos el comando `runlevel` que devuelve dos valores, el runlevel anterior y el actual.

Si queremos cambiar de runlevel sin rebotar el systema usamos `telinit rl`.
