# System architecture

## Change runlevels (boot targets) and shutdwon/reboot the system

Weight: 3

### Introduction

Unix uses separate processes to control distinct functions of the system (network applications, databases, on-demand configuration, etc.). These processes are called daemons or services
and are controlled by the service manager. The service manager is the first program launched by the kernel during the boot process, so its PID is always 1.

#### SysVinit

SysVinit is a service manager that controls services via shell scripts.

The boot sequence begins once the Linux kernel finishes initializing hardware drivers and mounting the root filesystem. The kernel then executes the `/sbin/init` binary as Process ID 1 (PID 1). As the parent of all subsequent processes, `init` immediately reads its primary configuration file, `/etc/inittab`, to determine the default target state, known as the default runlevel, and then executes early system preparation scripts (to set the system clock, enable swap space, check and mount remaining filesystems, and configure hostnames.).

Once system initialization completed, `init` invokes the main runlevel controller script passing the target runlevel number as an argument.

Los runlevels que usa `init` son:

- 0 shutdown
- 1 single user (modo rescate, sin red)
- 2 multi-user sin red
- 3 multi user con red
- 4 personalizable, normalmente no se usa
- 5 multi user con arranque gráfico
- 6 reinicio del sistema

En cuanto al fichero `inittab`, está formado por líneas con el formato `id:runlevels:action:process`.

- id es un ID de hasta 4 caracteres que identifica la línea
- runlevels es una lista de números de runlevel para los que se ejecutará el proceso indicado en esa línea
- action indica como afecta la ejecución de `process` al proceso `init`
- process es el proceso a ejecutar

Some valid actions for the `action` field are:

sysinit
: The process will be executed during system boot. It will be executed before any boot or bootwait entries. The runlevels field is ignored. 

boot
: The process will be executed during system boot. The runlevels field is ignored. 

bootwait
: The process will be executed during system boot, while `init` waits for its termination (e.g. /etc/rc). The runlevels field is ignored. 

ctrlaltdel
: The process will be executed when init receives the SIGINT signal. This means that someone on the system console has pressed the CTRL-ALT-DEL key combination. Typically one wants to execute some sort of shutdown either to get into single-user level or to reboot the machine. 

respawn
: The process will be restarted whenever it terminates (e.g. getty). 

wait
: The process will be started once when the specified runlevel is entered and init will wait for its termination. 

Vemos que los runlevels se ignoran cuando la acción está relacionada con el arranque del sistema (sysinit, boot, bootwait). Lógicamente, no se ignoran cuando la acción afecta
a runlevels específicos (wait, respawn). *wait hace que `init` pare hasta la terminación del proceso.

Por ejemplo:

~~~ zsh
# Default runlevel
id:3:initdefault:

# Boot-time system initialization script.
si::sysinit:/etc/init.d/rcS

# Actions taken on runlevel 3. init will wait until process finishes
~:S:wait:/sbib/sulogin
l3:3:wait:/etc/init.d/rc 3

# Action taken upon CTRL+ALT+DEL keystroke
ca::ctrlaltdel:/sbin/shutdown -r now

# Enable consoles for runlevels 2 and 3. The process will be restarted if it is terminated
1:23:respawn:/sbin/getty tty1 VC linux
2:23:respawn:/sbin/getty tty2 VC linux
~~~

En resumen, para arrancar el sistema:

1) se carga el kernel y este inicializa el hardware y el sistema raíz de ficheros
2) el kernel arranca el proceso `init` con PID 1
3) `init` lee el fichero `/etc/inittab` 
4) `init` identifica el runlevel por defecto
5) `init` ejecuta las acciones `sysinit`
6) `init` ejecuta las acciones `boot` y `bootwait`. El orden concreto depende de la configuración del fichero
7) `init` arranca el runlevel por defecto

Los scripts que necesita `init` para hacer el setup de cada runlevel están en `/etc/init.d`. 

Los scripts que hay que ejecutar al iniciar/detener un runlevel son links simbólicos que hay en `/etc/rc0.d`, `/etc/rc1.d` y que apuntan a `/etc/init.d`. Los enlaces que empiezan por S arrancan servicios y los que empiezan por K matan servicios. Por ejemplo, si el runlevel por defecto es 3 y arrancamos el sistema y tenemos el directorio

~~~ zsh
/etc/rc3.d/
├── S10network
├── S20syslog
├── S30sshd
├── S50cron
└── S99local
~~~

para arrancar el runlevel se ejecutaran los scripts en estricto orden alfabético.

Si venimos de otro runlevel, por ejemplo, pasamos del 2 al 3, se procesaran primero los enlaces que empiezan por K, también en estricto orden alfabético, para detener los servicios 
que no correspondan al nuevo runlevel.

Para saber en que runlevel estamos usamos el comando `runlevel` que devuelve dos valores, el runlevel anterior y el actual.

Si se modifica la configuración de `inittab` hay que recargarla con `telinit q`. Si queremos cambiar de runlevel sin rebotar el systema usamos `telinit rl`.
